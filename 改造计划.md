# FusionRec 电商系统改造计划

## 项目概述
基于现有 FusionRec 推荐系统，改造为支持餐饮/零售场景的完整电商系统，增加实时库存、多规格定价、多人协同点餐等高级功能。

---

## 一、新增功能模块

### 1. 实时库存状态显示
**功能描述：**
- 商品详情页显示实时库存数量
- 库存状态标签：充足(>100)、紧张(10-100)、即将售罄(1-10)、已售罄(0)
- 库存预警：当库存低于阈值时，后台自动提醒
- 库存锁定：下单时锁定库存，支付超时释放

**技术实现：**
```
前端：库存状态组件 + 实时WebSocket推送
后端：库存服务 + Redis缓存 + 分布式锁
数据库：sys_goods.stock_quantity 字段
```

### 2. 价格与规格选项系统
**功能描述：**
- 多规格支持：大/中/小份、颜色、尺寸等
- 规格组合定价：不同规格组合不同价格
- 加料/配料系统：可选配料，实时计算附加费用
- 规格图片：不同规格展示不同图片

**技术实现：**
```
数据库：
- sys_goods_sku (SKU表：规格组合)
- sys_goods_spec (规格名表：大小/颜色)
- sys_goods_spec_value (规格值表：大/中/小)
- sys_goods_sku_spec (SKU与规格关联表)

前端：规格选择器组件 + 价格计算器
```

### 3. 实时价格计算引擎
**功能描述：**
- 选择规格实时显示价格
- 数量增减自动计算总价
- 优惠活动实时抵扣
- 会员折扣自动计算

**计算公式：**
```
总价 = (SKU基础价格 + 配料价格) × 数量 × 会员折扣 - 优惠券抵扣
```

### 4. 订单备注与口味偏好
**功能描述：**
- 整单备注：配送要求、时间要求等
- 单品备注：口味偏好（少辣/多辣/不辣）
- 忌口标记：过敏源提醒（花生/海鲜/ gluten-free）
- 常用备注模板：快速选择常用备注

**数据库设计：**
```sql
-- 口味标签表
sys_taste_tag (tag_id, tag_name, tag_type: spicy/sweet/allergy)
-- 订单备注表  
user_order_remark (order_id, remark_type, content)
-- 单品备注表
order_detail_remark (detail_id, taste_tags[], avoid_tags[], custom_remark)
```

### 5. 多渠道支付系统
**支持支付方式：**
| 支付方式 | 接入方式 | 特点 |
|---------|---------|------|
| 微信支付 | 微信JSAPI/Native | 小程序+H5 |
| 支付宝 | 支付宝SDK | 手机网站+APP |
| 信用卡 | 银联/Stripe | 国际卡支持 |
| 现金 | 线下收银 | 到店支付 |
| 会员余额 | 系统内置 | 充值/消费/退款 |
| 混合支付 | 余额+第三方支付 | 组合支付 |

**支付流程：**
```
1. 创建订单 → 2. 选择支付方式 → 3. 调起支付 → 4. 支付回调 → 5. 订单确认
```

### 6. 多人协同点餐系统
**功能描述：**
- 生成共享桌号/二维码
- 多人同时扫码加入购物车
- 实时同步购物车内容
- 发起人确认下单
- 分摊金额计算

**核心功能：**
```
- 创建共享会话 (Create Share Session)
- 加入共享购物车 (Join Cart)
- 实时同步 (WebSocket Sync)
- 权限管理 (Owner/Member)
- 结算分摊 (Split Bill)
```

-- 商品库存表
CREATE TABLE `sys_goods_stock` (
  `stock_id` bigint(20) NOT NULL AUTO_INCREMENT,
  `goods_id` bigint(20) NOT NULL,

### 3.1 库存管理接口

```java
@RestController
@RequestMapping("/api/stock")
public class StockController {
    
    // 获取商品库存
    @GetMapping("/goods/{goodsId}")
    public ResultVo<StockVo> getGoodsStock(@PathVariable Long goodsId);
    
    // 锁定库存（下单时调用）
    @PostMapping("/lock")
    public ResultVo<Boolean> lockStock(@RequestBody LockStockDto dto);
    
    // 释放库存（支付超时/取消订单）
    @PostMapping("/unlock")
    public ResultVo<Boolean> unlockStock(@RequestBody UnlockStockDto dto);
    
    // 扣减库存（支付成功）
    @PostMapping("/deduct")
    public ResultVo<Boolean> deductStock(@RequestBody DeductStockDto dto);
    
    // 批量查询库存
    @PostMapping("/batch")
    public ResultVo<List<StockVo>> batchGetStock(@RequestBody List<Long> goodsIds);
}
```

## 八、风险与建议

1. **Lombok兼容性问题**：建议升级到最新版本或手动生成Getter/Setter
2. **支付安全**：需要接入官方SDK，做好签名验证
3. **并发库存**：使用Redis分布式锁防止超卖
4. **WebSocket稳定性**：需要心跳检测和重连机制
